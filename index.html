~/practica-mcp
public

Cliente y servidor MCP

Un chatbot de documentos que implementa ambos lados del Model Context Protocol con el SDK oficial: servidor con herramientas, recursos y prompts predefinidos, y un cliente que los conecta a un LLM (NVIDIA Nemotron) por stdio. Incluye las features avanzadas del protocolo: sampling (el servidor le pide al cliente que llame al LLM por él, sin tener su propia clave de API) y roots (el usuario decide qué carpetas del disco puede tocar el servidor) — además de una variante sobre transporte HTTP en 3 modos.

Probado con éxito: el modelo pide la lista de documentos antes de leer uno cuando no sabe qué existe, y relee un documento antes de editarlo sin que se le indique. Las pruebas de roots también revelaron y corrigieron un bug real: faltaba un await en la validación de permisos de list_directory, así que el acceso fuera del root nunca se bloqueaba.

Orquestador con subagentes

Un orquestador reparte un tema de investigación entre 3 subagentes independientes (técnico, casos de uso, riesgos) que corren en paralelo sin verse entre sí, y un sintetizador final integra los 3 hallazgos en un solo reporte coherente — el mismo patrón con el que Claude Code delega trabajo a subagentes.

Corrida real: los 3 subagentes respondieron en paralelo en 74.2s totales, y el reporte final integró los hallazgos en vez de solo pegarlos uno tras otro.

Pipeline RAG completo

Retrieval-Augmented Generation de punta a punta con embeddings 100% locales y gratuitos: tres estrategias de chunking, búsqueda semántica y BM25 combinadas por Reciprocal Rank Fusion, y respuestas con citas verificables al texto fuente exacto.

Para entender cómo funciona un RAG real — no solo mandarle el documento entero al modelo — sino segmentarlo bien, indexarlo por dos métodos distintos, y poder señalar de dónde salió cada respuesta.
